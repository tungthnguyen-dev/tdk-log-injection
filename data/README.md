# Dataset: labelled nginx access logs (v1.1)

## Files
- `frozen/access_v1.jsonl`: raw nginx log (JSON, one request per line). Never modified.
- `processed/events_labelled.csv`: parsed and labelled events, generated by `scripts/parse_logs.py`.

## How it was generated
- Isolated Docker testbed (`testbed/`): nginx (reverse proxy, JSON access log) in front of a small Flask app.
- Network `labnet` is `internal: true` (no Internet access).
- Benign traffic: `generators/benign.py`, 500 requests, seed 42, from 172.28.0.10.
- Attack traffic: `generators/attack.py`, 50 requests per class (200 total), seed 43, from 172.28.0.20.
- Both generators ran concurrently.

## Labels
- `label`: derived from source IP (172.28.0.10 = benign, 172.28.0.20 = attack).
- `attack_type`: none | path_scan | sqli | path_traversal | scanner_ua

## Columns
| Column | Description |
|---|---|
| event_id | Unique id, ordered by time (ev00000 ...) |
| time | Request time (ISO 8601) |
| remote_addr | Source IP. **Label source only, do not use as a feature** |
| method | HTTP method (attacker-controlled) |
| uri | Full request URI, raw (attacker-controlled) |
| protocol | HTTP version (attacker-controlled) |
| status | Response status code (server-generated) |
| bytes | Response body size (server-generated) |
| referer | Referer header (attacker-controlled) |
| user_agent | User-Agent header (attacker-controlled) |
| request_time | Processing time in seconds (server-generated) |
| label | benign / attack |
| attack_type | Attack class, `none` for benign |
| nginx_rejected | True if nginx rejected the request before reading headers (no URI/UA logged) |
| raw_log | Original log line as JSON, without the internal `exp_id` field. This is what the LLM sees in condition A |

## Counts
- benign: 500, attack: 200 (path_scan 50, sqli 50, path_traversal 50, scanner_ua 50)
- 30 of the 50 path_traversal requests were rejected by nginx while parsing the request
  line (status 400). nginx logs these without URI or headers, so `uri`, `user_agent`
  and `referer` are empty. They are marked `nginx_rejected = True`. Their attack_type
  was recovered from the generation order (verified by assertions in `parse_logs.py`).
- Injection targets are sampled only from events with `nginx_rejected = False`
  (20 path_traversal events are usable).

Status codes by type:

| attack_type | 200 | 302 | 400 | 404 | 500 |
|---|---|---|---|---|---|
| none | 443 | 24 | 0 | 33 | 0 |
| path_scan | 0 | 0 | 0 | 50 | 0 |
| path_traversal | 0 | 0 | 30 | 20 | 0 |
| scanner_ua | 50 | 0 | 0 | 0 | 0 |
| sqli | 15 | 0 | 0 | 3 | 32 |

## Known limitations
- Synthetic traffic: may be easier to classify than real-world traffic.
- Attack requests are sent faster than benign and fall within a short time window;
  do not use time-based features without accounting for this.
- Status 400 occurs only in the 30 nginx-rejected attack rows, never in benign traffic,
  so a detector may learn "400 = attack" as a shortcut.

## Software versions
- nginx: 1.30.5 (nginx:stable image)
- Python (generators): python:3.11-slim image
